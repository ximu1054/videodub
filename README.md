# VideoDub

把一段英文视频，整条换成中文配音——画面不动，时间轴对齐。

本地跑，视频不出本机。给你一个链接或者拖一个文件进去，等几分钟，拿一个中文版 mp4。

```
英文视频 ──▶ 语音识别 ──▶ 译成中文 ──▶ 合成配音 ──▶ 对齐时间轴 ──▶ 中文版 mp4
```

## 它解决什么问题

现成的「视频翻译」工具，多数只给你字幕。想要配音，得自己串三四套工具，最后
总会卡在同一件事上：**中文比英文长，念不完怎么办**。

压语速是唯一的手段，但压多少、什么时候压、压过头了怎么退回来——这些细节决定
成品听起来是「配音」还是「快进」。VideoDub 把这一层做成了算法：

| | 一句话 | 效果 |
|---|---|---|
| 可用时长 | 算到**下一句开口之前**，不是自己的结束时刻 | 句间停顿成了免费的余量，很多句子根本不用压 |
| 槽位按实际开口算 | 晚开口的句子自动多压一点，把欠的时间当场还掉 | 延迟不会自我放大 |
| 首句保护 | 整轨前移时首句顶到 0 之前，不压语速 | 开场不会比全片快一截 |
| 长度预算前置 | 译文超长就让模型重译短一点，而不是事后硬压 | 从源头消除「压不下」 |

最后一条是关键。同一个 30 分钟样本：译文守预算时，排布完的漂移是 **0.00 秒**；
不守预算时有 42 句压到 1.15 倍上限仍塞不进槽位，最大漂移 **16.5 秒**。
排布算法救不了太长的译文——只能不让它太长。

## 长什么样

一个本地网页。左边放链接或拖文件，右边是任务队列，四个阶段实时进度。

- 拖进去就能跑，默认参数已经调好
- 音色可以试听（8 个中文音色，含两个方言）
- 结果在页面里直接播放、下载
- 想调语速上限、偏移、伴奏，展开「高级」

跑完关掉浏览器就行，服务在后台，下次双击快捷方式还在。

## 安装

需要 **Python 3.11 或 3.12**（3.13 部分依赖还没跟上）。

```bash
git clone https://github.com/ximu1054/videodub.git
cd videodub
uv venv --python 3.12
uv pip install -e ".[dev]"
```

不用 uv 也行：

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -e ".[dev]"
```

`ffmpeg` 不用单独装——`imageio-ffmpeg` 自带一份，省得你折腾版本。

想用本机 GPU 跑翻译（不联网、免费）再加一组：

```bash
uv pip install -e ".[local-mt]"
```

## 用起来

```bash
videodub                        # 启动本地网页（默认，推荐）
videodub run video.mp4          # 命令行跑单个文件
videodub run "https://youtu.be/xxx"
videodub doctor                 # 体检：GPU、模型、ffmpeg、磁盘
videodub voices                 # 列出音色
```

第一次跑会下载模型（识别 2.9GB），之后离线可用。

**唯一需要联网的环节是配音合成**——中文语音走微软 Edge 的在线接口，免费、
不用 key，但要能连上。识别和翻译都可以完全离线。

### 合集（播放列表）

贴一个合集链接，网页上会多出一块选择区：只做当前这一集，还是整条合集逐集做完。

```bash
videodub run "https://www.youtube.com/playlist?list=xxx" --playlist            # 整条合集
videodub run "https://www.youtube.com/playlist?list=xxx" --playlist --limit 5  # 只做前 5 集
```

整条合集不是「一个大任务」，而是**一集一个任务**排进同一条队列。这样进度、
断点续跑、失败重跑、单集删除全都沿用现成逻辑。一百集就是一百条任务，串行跑，
关掉网页也不会中断（关掉程序才会）。

单次最多提交 100 集，超了就分批——这是防误触：`watch?v=…&list=…` 这种链接
很容易手滑把几千集全塞进队列。

点「开始配音」前会先花几秒试一次能不能下载。不行就不建任务，直接在界面上说
明原因，省得排一百集、看一屏红色才发现是同一个问题。

### 下载被 YouTube 拦了怎么办

报错 `Sign in to confirm you're not a bot` 有两个完全不同的成因，修法相反：

| 成因 | 怎么判断 | 怎么办 |
|---|---|---|
| cookies 里没有登录态 | `videodub doctor` 会说「导出时浏览器里没登录」 | 浏览器打开 youtube.com，确认右上角是自己的头像，再用 Get cookies.txt LOCALLY 重新导出，覆盖同一路径 |
| 登录态正常，节点 IP 被拦 | `videodub doctor` 会说「被拦的是节点出口 IP（x.x.x.x）」 | 在代理软件里换一个节点，再跑一次 `videodub doctor` 复测 |

`videodub doctor` 最后一行会直接给出结论，不用自己猜。程序读的是修改时间最新
的那份 `cookies.txt`（`%APPDATA%\yt-dlp`、下载、桌面都会找），所以重新导出后
不必手动删除旧文件。

## 配置

改 `videodub.toml`（放在数据目录里，`videodub config` 会告诉你路径）：

```toml
[tts]
voice = "zh-CN-XiaoxiaoNeural"   # videodub voices 看全部
rate = "+8%"                     # 基础语速

[render]
max_tempo = 1.15                 # 单句语速压缩上限，越小越自然

[mt]
backend = "auto"                 # auto | local | api

[mt.api]
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"
# key 放环境变量 VIDEODUB_API_KEY，别写进文件
```

翻译后端怎么选：

- **api**：最快最准，几毛钱一部片。任何 OpenAI 兼容接口都行
- **local**：Qwen2.5-3B 跑在本机，免费、离线，慢一些、语气略生硬
- **auto**：配了 key 就走 api，否则走 local

## 性能参考

30 分钟 1080p 视频，RTX 4070 Ti：

| 阶段 | 耗时 |
|---|---|
| 下载 | 12 秒 |
| 识别（large-v3） | 2 分钟 |
| 翻译（API） | 5 分钟 |
| 配音 + 对齐 + 封装 | 3 分钟 |

显存峰值约 9GB。纯 CPU 也能跑，慢 4 倍左右。

## 不做什么

说清楚边界，省得你试了才发现：

- **不做口型同步**，只对齐时间轴
- **单音色**。多人对话目前都用同一个声音（多音色在路线图里）
- **BGM 要自己带**。内置的人声分离是实验性的，请自备伴奏文件，混音时自动闪避人声
- **不做字幕烧录**
- **只做中英**。译成其他语言需要换提示词，不难但没做
