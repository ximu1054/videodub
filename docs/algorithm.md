# 时间轴是怎么对齐的

这份文档解释 `src/videodub/stages/align.py` 与 `units.py` 里的每个决定。
如果你只想改「语速太快了」这类体验问题，看最后一节就够。

## 问题的形状

配音的基本矛盾：**中文念一段内容，通常比英文花更长时间**。

英文 10 秒说完的句子，中文往往要 11~13 秒。而画面不会等你。于是每一句都
面临一个选择：要么压语速念快一点，要么让它晚一点结束——而晚结束会挤压下一句，
再下一句，一路累积。

旧实现选的是「晚一点就晚一点」：

```python
start_at = max(target, cursor)     # cursor = 上一句结束时刻
cursor   = start_at + duration
```

一行代码，看起来无害。问题是它只顺延、从不追回：一旦晚了 2 秒，后面就永远
晚 2 秒以上。30 分钟的样本上，这个延迟累积到 **16 秒**——片尾的中文比画面
慢了整整一句半。

## 三个修法

### 一、可用时长算到「下一句开口」

```python
slot = next_start - start - guard      # 而不是 end - start
```

句与句之间的停顿本来就是空的。把这段停顿算进可用时间，很多句子压根不需要
压语速——它们只是原来的槽位算窄了。

样本里 182 句平均槽位 8.4 秒，其中约 1 秒来自句间停顿。这一条单独就能让
需要压缩的句子少三成。

### 二、槽位按「实际开口时刻」算

这是修掉累积延迟的那一刀。

原写法用**原片时刻**（`next_ideal - ideal`）算槽位。于是一句晚了 3 秒开口，
它仍然以为自己有完整的一段槽位，结果必然又越过下一句的起点——延迟自我复制。

改成用**实际开口时刻**（`next_start - actual_start`）之后，晚开口的句子会
自动发现「我的时间变少了」，于是多压一点，把欠的时间当场还掉。

代价是：晚开口的句子听起来会更急。但它的急只持续一句，而不是让后面每一句都晚。

实测（同一份 182 句样本，语速上限 1.15 倍）：

| | 旧实现 | 新实现 |
|---|---|---|
| 最大漂移 | 16.9 秒 | 16.6 秒 |
| 平均偏移 | 0.99 秒 | 0.69 秒 |
| 偏移超 1 秒的句数 | 36 | 28 |

注意最大漂移几乎没变——它由一句「译文长度是原声 4 倍」的异常句决定，排布
再怎么改都救不了。这引出第三条。

### 三、长度预算前置到翻译阶段

`units.audit_budget()` 在译文拿到之后逐句核算：

```python
slot        = next_start - start - guard
预计语速时长 = 汉字数 / 4.6 + 英文数字折算
ok         = 预计时长 <= slot * 1.15
```

超了就带上「压到 N 个字以内」的约束重译这一句。注意**只重译这一句**，
其余译文不动——大批重译会把已经通顺的上下文又搅乱。

这一步才是真正把漂移归零的环节。同一份样本，把超预算的句子按预算裁短后
重跑排布：**最大漂移 0.00 秒，没有任何一句需要压语速**。

所以渲染报告里，`overflowed`（压到上限仍塞不下的句数）比 `drift_max`
更值得看：它指出的是「翻译没做好」，而不是「排布没做好」。

## 两个保护

**首句保护**（`head_clamped`）。整条音轨前移补偿音画错位时（`offset` 为负），
第一句会顶到 0 之前。此时不能压它的语速——那会让开场比全片快一截，听起来
像赶进度。让它顺延即可，观众感知到的是「开场稍等了一下」，而不是「这个人说话变快了」。

**提前开口有上限**（`early_max=0.35`）。一句太长的译文，可以借用前一句留下的
空隙提前开口，但最多提前 0.35 秒。再多就会让观众觉得「声音抢在画面之前」。

## 关于 `trim_silence`

TTS 输出首尾各带 100~400 毫秒空白。合成后立刻裁掉（保留 30 毫秒防止削掉
字头的爆破音），短句能省 0.3~0.8 秒。

这看着像小事，但它是**免费的**时间——裁掉的是静音，不是内容。182 句累计
省下约 70 秒，相当于把整片需要的语速压缩量降了将近三成。

它还有个副作用是好的：裁过静音之后再算时长，排布器拿到的数字才是它真正
要面对的数字。不做这一步，规划器会以为每句都长了 0.4 秒，从而过度压缩。

## 想调音色手感时看哪里

| 症状 | 改什么 |
|---|---|
| 整体太赶 | `rate` 调低（如 `+0%`），或 `max_tempo` 降到 1.1 |
| 个别句子听着别扭、变快 | `max_tempo` 降到 1.05，代价是更多句会顺延 |
| 声音比画面慢半拍且全片一致 | `offset` 设负值，如 `-0.15` |
| 声音比画面快 | `offset` 设正值 |
| 两句之间太挤 | 调大 `render.GUARD`（代码里，默认 0.06 秒） |

`max_tempo` 是最值得动的旋钮。1.15 是「听不出快」与「装得下」的折中；
1.05 明显更自然，但会更频繁地顺延；1.25 以上会被听出来。
